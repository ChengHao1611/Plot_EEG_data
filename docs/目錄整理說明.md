## 共通資料格式與命名

### EEG EDF

`data/raw_edf/eeg/` 的一般 EEG 檔案供 α 波、眼動與 Status 事件流程使用。抽查的 EDF 含下列 9 個通道，取樣率為 500 Hz：

```text
FP1, FP2, C3, CZ, C4, O1, OZ, O2, Status
```

`data/raw_edf/auxiliary/s01_060926_1n_car_position.EDF` 含下列 7 個通道，供車道偏移分析使用：

```text
FP1, FP2, O1, OZ, O2, vehicle position, Status
```

### DAT

所有 DAT 都以逗號分隔，第一個數字是筆數，後續數字是秒數：

```text
3,15,48,120
```

### 駕駛狀態事件 Excel

`eeg_analysis/driving_state/predict_algorithm.py` 至少需要英文欄位：

```text
second, react_time
```

現有的 `data/derived/feature_tables/s09_060313n_raw_status_and_30s_eyeblink.xlsx` 欄位為：

```text
second, eyeblinking_count, react_time, sleep
```

## 自動 α 波與眼動偵測

### `eeg_analysis/detection/detect_alpha_and_eyeblink.py`

此為自動偵測的命令列入口。它從 EDF 找出 FP1、FP2，使用 FP2 進行眼動與 α 波偵測。

| 項目 | 說明 |
| --- | --- |
| 必填輸入 | `--file <EEG EDF 路徑>`；未提供時會互動詢問。 |
| 指令 | `python -m eeg_analysis.detection.detect_alpha_and_eyeblink --file data/raw_edf/eeg/s01_061102n_raw.EDF` |
| 輸出 | 在輸入 EDF 同資料夾寫入 `Alpha.dat` 與 `eyeblink.dat`。 |
| DAT 內容 | 第一個數字為筆數；後續為偵測到的秒數。 |

### `eeg_analysis/detection/record_alpha.py`

Alpha偵測使用1 Hz高通、30 Hz低通與逐秒FFT，分別累加Theta（4–7 Hz）、Alpha（8–12 Hz）及Beta（13–20 Hz）的 `Amplitude²`。程式會依實際取樣率與FFT長度，動態選擇最接近頻帶上下限的FFT bin；例如500 Hz、512點FFT時，Alpha使用索引8～12，即7.8125～11.71875 Hz。眼動秒不進行FFT；其餘秒數只有在 `Alpha > Theta` 且 `Alpha > Beta` 時才寫入DAT。此模組可由整合流程呼叫，也可獨立從命令列執行。

| 項目 | 說明 |
| --- | --- |
| 函式輸入 | EDF路徑、輸出DAT路徑、可選通道名稱、眼動秒數與分析秒數範圍。 |
| 指令 | `python -m eeg_analysis.detection.record_alpha --file <EDF> --eye-dat <眼動DAT> --end-second 300` |
| 輸出 | 符合Alpha條件的秒數DAT，函式另回傳逐秒Theta／Alpha／Beta Power。 |
| DAT內容 | 第一個數字為符合條件的秒數量，後續為向上取整後的一基秒數。 |

### `eeg_analysis/detection/record_arousal.py`

眼動尖峰偵測的函式庫，由自動偵測主程式呼叫，沒有獨立命令列介面。

| 項目 | 說明 |
| --- | --- |
| 函式輸入 | MNE Raw 物件、FP1／FP2 通道、輸出 DAT 路徑。 |
| 輸出 | 指定路徑的眼動秒數 DAT。 |
| 主要預設 | 動態高度閾值為 `median + 0.5 × MAD`，prominence 門檻為 `0.00007`。 |

## 疲勞駕駛預測系統：功能一

### `eeg_analysis/fatigue_driving_prediction_system/function_one.py`

此命令讀取單一EDF，以Status 251／252作為偏移開始、253作為導正開始，將事件時間向上取整，並將Reaction Time以一般四捨五入記錄至小數點第一位後檢查第1～300秒。每個事件以 `[s-90, s]` 內截至當次已發生、且包含當次事件的RT平均作為Global RT；前90秒不判Local／Global持續疲勞，第90秒起須同時符合 `Local RT >= 1.6` 與 `Global RT >= 1.6`。任何 `Local RT >= 3.2` 的Critical Lapse都會立即觸發，包括前90秒暖機期。前300秒出現任一觸發即排除資料；否則以 `min(1.6, ceil_0.1(mean RT × 1.5))` 建立個人化RT門檻，並建立後續生理評分所需的眼動與Alpha robust baseline。

```powershell
python -m eeg_analysis.fatigue_driving_prediction_system.function_one --file data/raw_edf/eeg/s11_060920_1n_raw.edf
```

預設輸出至 `data/derived/fatigue_driving_prediction_system/<record_id>/`，包含 `reaction_time_events.xlsx`、`function_one_results.xlsx` 與 `rt_validation.png`。`function_one_results.xlsx` 逐事件保存Local／Global RT、active threshold、Local／Global exceed、持續疲勞、Critical Lapse與觸發原因；`rt_validation.png` 顯示90秒暖機區、1.6秒Phase 1門檻及3.2秒Critical門檻。通過篩檢的資料另有眼動與Alpha輸出，並預設直接進入功能二；加入 `--function-one-only` 可停止在功能一。

## 疲勞駕駛預測系統：功能二

### `eeg_analysis/fatigue_driving_prediction_system/function_two.py`

不帶參數執行功能二時，程式會讀取repository根目錄的 `train_data`，依清單順序在 `data/raw_edf/eeg/` 遞迴尋找 `<record_id>_raw.EDF`，並為每筆資料依序執行Phase 1與Phase 2。Phase 1未通過時仍會匯出 `function_two_results.xlsx`，Phase 2狀態記為 `SKIPPED_FUNCTION_ONE_NOT_PASSED`；單筆缺檔或失敗不會中止後續資料，而會寫入批次摘要。可用 `--manifest`、`--edf-dir`及`--results-root`覆寫預設位置。

```powershell
python -m eeg_analysis.fatigue_driving_prediction_system.function_two
```

批次預設輸出根目錄為 `data/derived/fatigue_driving_prediction_system/`，每個record ID有自己的子資料夾，另產生總表 `training_batch_results.xlsx`。單筆資料夾包含Phase 1的 `function_one_results.xlsx` 與Phase 2的 `function_two_results.xlsx`；完整Phase 2另包含 `eyeblink_function_two.dat`、`Alpha_function_two.dat`、`behavioral_rt_debug.png`及`function_two_pre_fatigue_90s.png`。若要保留單一EDF模式，使用 `--file <EDF路徑>`，並可搭配 `--output-dir <資料夾>`。

Phase 2的Global RT沿用前300秒事件，不重新暖機；第300秒後第一個Local／Global同時達個人門檻的事件或3.2秒Critical Lapse，就是Behavioral Fatigue Onset。功能二以30秒眼動／Alpha窗口的robust Z分數產生生理警報，目前條件為Z-Alpha與Z-Eye皆`>= 0.8`且連續4秒，再與onset比較提前時間。生理scale依序使用單筆MAD、IQR及固定pooled fallback；pooled常數為Alpha `1.4826`、Eye `4.4478`，執行時不重新讀取train_data，可由同名命令列參數覆寫。Function Two與Observe圖不顯示聯合分數曲線或30–60秒目標區間陰影。

## α 波人工標註驗證

### `eeg_analysis/alpha_validation/alpha_validation.py`

此程式把 EDF 的自動 α 波判定與人工 α DAT 比較，輸出 true／false／miss 的逐秒時域與頻域圖。

| 項目 | 說明 |
| --- | --- |
| 必填輸入 | 位置參數 `<資料夾或 raw EDF 路徑>`。資料夾模式下必須只含一個 `*_raw.EDF`。 |
| 必要旁檔 | 與 EDF 同資料夾的 `<record_id>_alpha.dat`；`record_id` 會移除 EDF 檔名尾端的 `_raw`。 |
| 可選眼動 DAT | `<record_id>_raw_arousal info.dat` 或 `<record_id>_arousal info.dat`；其秒數會從 α 偵測結果排除。 |
| 常用參數 | `--channel FP2`、`--alpha-threshold 1000`、`--plot-dir <資料夾>`、`--normal-dist-output <PNG>`、`--highpass`、`--lowpass`、`--nfft-pow2`、`--max-plot-freq 100`。 |
| 頻帶參數 | `--alpha-low 7.8`、`--alpha-high 12.5`、`--peak-low 1.9`、`--peak-high 30`；也接受 theta／beta 參數，但目前運算沒有使用 theta／beta 值。 |
| 指令 | `python -m eeg_analysis.alpha_validation.alpha_validation data/raw_edf/eeg/s01_061102n_raw.EDF` |
| 預設輸出資料夾 | `<record_id>_alpha_detection_plots/`，位於 EDF 同資料夾。 |
| 輸出檔案 | `true/s00001_true.png`、`false/...png`、`miss/...png`，以及 `<record_id>_alpha_energy_normal_distribution.png`。 |

注意：`--notch-freq` 雖可傳入，但目前套用 notch 的程式碼被註解，不會生效。

### `alpha_detection_paths.py`、`alpha_detection_plotting.py`、`alpha_detection_distribution.py`

這三個檔案是 `alpha_validation.py` 的輔助模組，沒有獨立命令列介面。

| 檔案 | 用途 | 輸出 |
| --- | --- | --- |
| `alpha_detection_paths.py` | 尋找 EDF、人工 α DAT、可選人工眼動 DAT，並建立預設圖檔位置。 | 無直接輸出。 |
| `alpha_detection_plotting.py` | 產生 true／false／miss 的逐秒時域與頻域圖。 | PNG。 |
| `alpha_detection_distribution.py` | 將 true+miss 與 false 的 α 能量畫成直方圖與常態擬合。 | PNG。 |

## 眼動驗證與分布

### `eeg_analysis/eye_movement/eye_movement_validation.py`

| 項目 | 說明 |

## 駕駛狀態 GUI

### `eeg_analysis/driving_state/predict_algorithm.py`

目前正式使用的 Tkinter GUI，提供三種模式。沒有命令列參數，請直接啟動視窗並選檔。

| 項目 | 說明 |
| --- | --- |
| 啟動 | `python -m eeg_analysis.driving_state.predict_algorithm` |
| 必填輸入 | 事件 Excel、α DAT、眼動 DAT；三者都必須在 GUI 選擇。 |
| Excel 欄位 | 至少需有 `second` 與 `react_time`。 |
| DAT 限制 | 檔名不限，但內容要是「筆數,秒數...」格式。 |
| 模式一 | 逐筆顯示事件前 `30 + react_time` 秒到事件後 5 秒的 α／眼動累積。 |
| 模式二 | 顯示全時程 α、眼動與反應時間趨勢圖。 |
| 模式三 | 顯示預測與實際駕駛狀態，並輸出報表。 |
| 模式三輸出 | 在啟動程式時的目前工作目錄寫入 `駕駛狀態分析結果.xlsx`，欄位為 `Second、Eye_Sum、Alpha_Sum、React_time、Eye_Alarm、Alpha_Alarm、Pred_State`。 |
| 累積視窗 | α 為 10 秒、眼動為 30 秒。 |

### `eeg_analysis/driving_state/legacy/sort_event.py`

舊版駕駛狀態 GUI。輸入與輸出格式和正式版相近，但 α 累積視窗為 1 秒，判定邏輯也略有不同；除非需要重現舊結果，否則優先使用 `predict_algorithm.py`。

### `eeg_analysis/statistics_30s_alpha_eyeblink_of_fatigue/observe.py`

此 Tkinter GUI 的行為疲勞 onset 與 `fatigue_driving_prediction_system/function_two.py` 共用同一評估器，適合檢查目前兩階段演算法的行為與生理判定結果。

| 項目 | 說明 |
| --- | --- |
| 啟動 | `python -m eeg_analysis.statistics_30s_alpha_eyeblink_of_fatigue.observe` |
| 必填輸入 | 事件 Excel、Alpha DAT、眼動 DAT。 |
| 事件欄位 | 支援 `second`／`react_time`、逐秒統計表中文欄位，以及 `reaction_time_events.xlsx` 的事件秒數／Local RT 欄位。 |
| RT 正規化 | 事件秒數向上取整為整數；Local RT 以一般四捨五入取至小數第一位。 |
| 個人化門檻 | 由使用者在介面手動輸入大於 0 的有限數值；Observe 不會從前 300 秒自動計算或修改輸入值。 |
| Pooled scale | Alpha與Eye皆由介面手動輸入，預設分別為 `1.4826`、`4.4478`；僅在該筆MAD與IQR皆為0時使用。Observe不會自動讀取`train_data`。 |
| 行為 onset | 從整段資料開始搜尋第一個 `(Local >= 個人門檻且 Global90 >= 個人門檻)` 或 `Local >= 3.2` 的事件；Global RT使用包含當次事件的`[s-90, s]`。前300秒觸發代表Phase 1排除。 |
| onset 後狀態 | 第一個行為觸發後維持 Fatigue，與功能二以第一個 onset 作為預測目標的語意一致。 |
| Phase 1 圖表 | 若第一次行為疲勞在第300秒（含）以前，僅顯示上方累積特徵、RT與行為疲勞；不顯示Phase 2、生理疲勞標記及下方生理判定圖。 |
| 圖表時間 | 顯示至 `min(第一次行為疲勞時間 + 500秒, recording總時間)`；未觸發時顯示完整時間。 |
| 輸出 | `data/observe/<record_id>_observe.png` 與同名 XLSX；XLSX 包含門檻、Global RT、Local／Global exceed、Critical Lapse及觸發原因。 |

## 30 秒眼動／α 波疲勞事件統計

### `eeg_analysis/statistics_30s_alpha_eyeblink_of_fatigue/record_status_and_eyeblink_to_xlsx.py`

從 Status 通道建立完整逐秒資料表；它將 α 波以 10 秒滑動視窗、眼動以 30 秒滑動視窗補入表格，作為疲勞事件統計的輸入。

| 項目 | 說明 |
| --- | --- |
| 啟動 | `python -m eeg_analysis.statistics_30s_alpha_eyeblink_of_fatigue.record_status_and_eyeblink_to_xlsx` |
| 互動輸入 | EDF 路徑。 |
| EDF 條件 | 必須含 `Status` 通道。程式將大於 1 的連續 Status 值依序視為事件開始、反應、回復。 |
| 可選 α DAT | EDF 同資料夾的 `<record_id>_alpha.dat`。 |

## 實驗與原型

### `tools/experiments/check.py`

人工與自動眼動 DAT 的簡易比對工具。輸入檔案路徑目前寫死為其他資料夾，沒有命令列參數；執行後會在目前目錄輸出 `comparison_details.txt`。適合作為程式碼參考，不建議直接用於目前資料夾。

### `tools/experiments/GetAlpha.java`

Java／Android 用的 α 波 FFT 原型。以 `detectAlpha(double[] data, int fs)` 接收資料與取樣率，回傳每秒 α 判定 `alphaMatrix` 及每 30 秒移動量 `movement`。它不讀寫檔案，且需 JDSP (`FastFourier`) 函式庫；目前沒有建置設定。
